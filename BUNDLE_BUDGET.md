# Bundle Budget

Markpad uses the operating system webview and embeds a production frontend inside one Go binary.

## Current release shape

| Artifact | Current size | Policy |
|---|---:|---:|
| Stripped Linux binary | 10,306,440 bytes (9.83 MiB) | hard ceiling 16 MiB |
| Stripped Windows binary | 16,775,680 bytes (15.999 MiB) | hard ceiling 16 MiB |
| Frontend JavaScript | 4,553,072 bytes (4.34 MiB) raw, code-split | avoid unbounded growth |
| Frontend CSS | 126,167 bytes (123.2 KiB) raw | generated by Tailwind |

Sizes were measured from the v0.13.0 release candidate on 2026-09-02. The redesigned workbench, responsive source viewers, incremental CodeMirror editor, modern Markdown/Mermaid support, bounded relative-image loading, unified assets, and strengthened interaction contracts remain inside the 16 MiB binary ceiling.

The Windows figures were re-measured on 2026-09-02 after the workbench redesign, modern Markdown pass, and responsive source-viewer fix. Full Mermaid 11 support adds about 3.29 MiB to the stripped Windows binary, so the hard ceiling moved from 15 MiB to 16 MiB. Mermaid is split into lazy chunks and is not fetched or evaluated until a document contains a Mermaid fence; ordinary notes retain the smaller startup path. The runtime remains offline and does not ship a browser engine.

The Settings/theme pass plus unified keyboard system adds one focused runtime dependency: `@tanstack/react-hotkeys@0.10.0`. It replaces the app-wide manual action listener, provides platform-aware `Mod` handling and live registration metadata, and lets Settings render the shortcuts that are actually active. Its core/store packages are bundled locally and make no runtime network calls.

The CodeMirror editor pass adds the modular CodeMirror 6 core and lazy language
modes without changing the runtime boundary. Local stripped Windows builds made
with the release-pinned Bun 1.3.14 measured 16,775,680 bytes (15.999 MiB) for
amd64 and 15,803,392 bytes (15.07 MiB) for arm64. Both remain below the 16 MiB
ceiling; production builds also drop dependency console and debugger
statements. The amd64 artifact has 1,536 bytes of remaining headroom,
so further embedded growth requires a compensating reduction. Language chunks
are embedded for offline use but loaded by the editor only when a matching
source file is opened; the existing bounded Highlight.js renderer remains the
static-viewer fallback.

`node_modules`, Bun, TypeScript, Oxlint, Oxfmt, tests, examples, and source maps are development inputs. They are not embedded in the release.

## Runtime memory

WebKitGTK uses separate application, network, and renderer processes. Use proportional set size (PSS), not summed RSS, because RSS double-counts shared pages.

The operating-system webview is the dominant memory cost. Keep document-specific allocations bounded:

- Editable text reads are capped by the Go boundary.
- Images are capped at 50 MiB.
- Syntax highlighting is skipped for very large content.
- Edit history is capped by state count and total text.
- Saved history is capped at 50 snapshots per document.
- PDF data is not loaded into Markpad.
- Workspace scans include at most 10,000 files, visit at most 100,000 entries, descend at most 32 levels, and accept files no larger than 2 MiB.
- Each workspace search reads at most 64 MiB and returns at most 200 results; it has no persistent index.
- Pre-save source verification stream-hashes at most 10 MiB and stores one SHA-256 digest plus filesystem identity per open saved document.

### Windows measurement note

Task Manager's top-level `markpad.exe` row is not the whole application. On the 2026-09-01 Windows QA machine, the rebuilt warm blank app showed 35.6 MiB working set in the Go host and 352.7 MiB summed working set / 162.3 MiB private bytes across the eight-process Markpad/WebView2 tree. Summed working set double-counts shared pages, so private bytes are the more useful comparison on Windows. This is a single-machine warm snapshot, not a cross-machine benchmark.

For reference, DBX on that machine measured 424.0 MiB summed working set / 176.3 MiB private bytes across seven processes. Markpad is still below the binary-size budget and opens warmly in about 376 ms, but its WebView2 renderer remains the main memory target; the apparent 35 MiB host-only number must not be used as the total.

## Dependency rules

- No Electron, browser engine, runtime CDN, telemetry, or cloud client.
- No component suite or general state-management package.
- Browser packages must be bundled and embedded.
- Import icons statically so unused icons are removed.
- Build tools stay in `devDependencies`.
- Direct package versions stay pinned and `bun.lock` stays committed.

## Release checks

1. Run `make setup` from a clean dependency tree.
2. Run `make check`.
3. Run `make build`.
4. Confirm `dist/markpad` is no larger than 16 MiB.
5. Confirm no production asset references an HTTP URL.
6. Exercise Markdown, code, text, image, and PDF handoff offline.
7. Exercise folder open, `Ctrl+P`, `Ctrl+Shift+F`, match selection, file creation, refresh, and confirmed deletion.
