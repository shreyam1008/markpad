# Task v1: finished workflow — 2026-09-13

This completes the scoped one-file task workflow. It is a locally tested
candidate, not a published release or a claim of feature parity with ZenNotes.
See [the user guide](tasks.md) for the full interaction and storage contract.

## What the upstream study established

Upstream ZenNotes 2.48.0 was run in the isolated temporary study folder described
in [the spacing study](zennotes-spacing-study-2026-09.md). This follow-up created
the disposable `Study task lifecycle` task, opened its action menu and changed it
to In progress. The card moved to that column; the resulting Markdown file
contains `title`, `status: in-progress`, `tags: [task]` and `dateCreated` frontmatter.

![Upstream task actions](../dist/zennotes-study/captures/06-task-actions.png)

Source review followed `TasksView.tsx`, `TasksRow.tsx`, `TasksKanban.tsx`, shared
task parsing, and `store.ts` creation/toggle/reorder paths around lines 5162,
5512 and 7705. This was targeted lifecycle review; not every upstream feature
was executed or audited.

| Concern | ZenNotes implementation | Quillpane v1 decision |
|---|---|---|
| Storage | Checkbox tasks inside notes plus separate frontmatter task files | One marked Markdown file containing the whole list/board |
| Organization | Status, priority, folder/custom status; calendar and saved filters | Optional categories: tags in List, columns in Board; completion separate |
| Editing | Prefer the live note buffer, route changes through normal persistence | All task transforms use the current document buffer and existing recovery/save pipeline |
| Reordering | Rewrite Markdown order; follow task after a move | Visible row order in List without changing category; category order in Board |
| Notes and naming | Open the underlying note | Open the exact task line or board heading in Quillpane's Editor |
| Cleanup | Different actions for task state and underlying note lifecycle | Recoverable task Trash inside the same file; explicit confirmation before clearing |

No vault scan, watcher, calendar, date parser, priorities, separate file per task,
or dependency was introduced. Those are different product choices from the
user's requested category model. The on-disk task format did not change.

## Completed interactions

- Create a marked Markdown task document, add tasks repeatedly, switch List/Board,
  assign categories, check/reopen tasks and search titles/categories/attached notes.
- Rename/remove/order categories. Empty categories persist; Untagged remains first.
- Reorder against visible List neighbors while preserving both categories. Board
  neighbors remain within their column; dragging across columns assigns category.
- New task creation clears filters so the added task stays visible. Filtered empty
  states offer accurate guidance; shown/total counts distinguish filtered results.
- Apply inline title changes explicitly or keep valid changes when focus leaves
  the form; Escape/Cancel cancel them. Reordering is disabled while the title has
  unapplied edits. Notes and board naming use the existing Editor at the exact line.
- Move all completed tasks to recoverable Trash with a count and an explicit
  warning that hidden tasks are included. Cancel leaves them intact. Restore all
  preserves titles, completion, categories, notes and source order.
- Existing clear-Trash confirmation, document Undo/Redo, recovery drafts, atomic
  saves, external-change protection and bounded source fallback remain in place.

Trash/restore, category ordering and cross-category before/after moves. TypeScript,
lint and formatting pass with the pre-existing React compiler warnings unchanged.
Canonical Go tests/vet, release metadata and offline asset scan pass.

**67 native Windows checks** pass. The expanded checks exercise creation,
categorization, rename/remove/order, filtering, notes search, drag/drop, visible
reordering, bulk cleanup cancellation, Restore all, source navigation/caret
position, title blur recovery and Escape cancellation, persistence, undo/redo,
twelve palette/mode combinations, narrow windows, scaling, reduced motion,
500 tasks, the 501-task full-source fallback and window/unsaved-close controls.

The reference engine is WebView2 152.0.4191.66. First contentful paint in the final
profiling run was about **745 ms** from launch; 500 task rows became visible in
about **179 ms** (100 ms polling resolution). Process-tree private-memory
snapshots after forced JS GC were **209.9 MiB** after the extended six-task/theme
workflow, **227.3 MiB** for 500 List tasks and **240.6 MiB** for 500 Board tasks.

open; no speedup or RAM floor is claimed. Raw evidence:
